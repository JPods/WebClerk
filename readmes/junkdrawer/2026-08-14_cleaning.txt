  Now, item 3 — dangerouslySetInnerHTML. The five uses are all for JSON syntax
  highlighting via a syntaxHighlightJson() function that wraps JSON tokens in   
  <span> tags using regex. Currently safe because the input is always
  JSON.stringify()'d first (which escapes HTML), but it's fragile — one refactor
   that passes raw user content and it becomes XSS.               

  Two options:

  A. Replace with React components — a <HighlightedJson> component that splits  
  the string and returns <span> elements. No dangerouslySetInnerHTML at all.
  Zero XSS surface.                                                             
                                                                  
  B. Keep the regex approach but run through DOMPurify — less work, still uses  
  innerHTML but sanitized. Leaves the fragile pattern in place.
                                                                                
  I'd recommend A — it's the single-source-of-truth approach. One component,    
  five call sites updated, no innerHTML anywhere. Want me to build it?
