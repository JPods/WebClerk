  What Would Actually Move the Needle

  1. Business-context vectors (yes — this is the big one)                       
   
  Alice should build vectors from this installation's data, not just the        
  codebase:                                                      
                                                                                
  - Transaction patterns: "Your top 5 customers order weekly. Customer X hasn't 
  ordered in 60 days."
  - Workflow sequences: "Users at this installation always create proposals     
  before orders" (observed, not assumed)                                        
  - Field usage: "The po_number field is filled on 90% of your orders — it
  matters here" vs. an installation where nobody uses it                        
  - Product knowledge: "Item SKU-4521 is your highest-margin product. It's in 3
  open orders."                                                                 
                                                                 
  Alice already runs alice-patterns.py every 4 hours against the commerce       
  database. What she doesn't do is vectorize those patterns so she can answer
  conversational questions about the business. That's the gap.                  
                                                                 
  2. Shift the vector store from code-first to user-first                       
   
  Split Alice's vectors into two collections:                                   
                                                                 
  ┌────────────┬────────────────────────────────────────────┬───────────────┐   
  │ Collection │                   Source                   │ Who it serves │
  ├────────────┼────────────────────────────────────────────┼───────────────┤
  │ alice_code │ WC3 source, models, services               │ Claude,       │
  │            │                                            │ developers    │
  ├────────────┼────────────────────────────────────────────┼───────────────┤   
  │            │ Q&A corpus, coaching content, business     │ Users via     │   
  │ alice_user │ patterns, transaction history summaries,   │ chat widget   │   
  │            │ flowchart descriptions                     │               │   
  └────────────┴────────────────────────────────────────────┴───────────────┘

  When a user asks a question, Alice searches alice_user first. When Claude     
  asks, Alice searches alice_code. Same LLM, different knowledge base.
                                                                                
  3. Contextual micro-help at the point of action                

  The AliceHintBar is passive — it shows tips when the page loads. What Alice   
  should do:
                                                                                
  - First-time detection: "This is your first invoice. Want a 30-second         
  walkthrough?" (tracked in contact.metadata)
  - Error prevention: "You're about to save an order with no ship-to address.   
  80% of your orders have one."                                                 
  - What-changed announcements: When WC_HQ pushes an update, Alice says "New:
  you can now drag columns. Try it."                                            
  - Idle coaching: User hasn't touched a feature for 30 days → Alice surfaces a
  tip about it
