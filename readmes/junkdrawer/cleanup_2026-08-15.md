  CRITICAL — Security & Correctness Errors                        
                                                                                
  1. DELETE via HTTP GET
                                                                                
  src/api/wcapi.ts:489 — deleteRecord uses apiClient.get("/wcapi/delete/", {    
  params }). GET requests can be triggered by image tags, prefetch, browser
  caching, and URL logging. A malicious link could delete records.              
                                                                  
  2. PermissionsContext bypasses auth entirely                                  
  
  src/context/PermissionsContext.tsx:76 — Uses raw fetch() instead of apiClient.
   No Authorization: Bearer header, no token refresh, no request tracking. Also
  carries a "use client" Next.js directive (line 2) that does nothing in this   
  Vite project.                                                   

  3. PermissionsProvider defined but never mounted

  PermissionsContext.tsx defines the provider, but it appears nowhere in App.tsx
   or main.tsx. The RBAC permission system is built but not wired in.
                                                                                
  4. login/logout swallow errors as data                          

  src/api/auth.ts:156-158 — catch (error: any) { return error.response?.data || 
  error.message }. Callers can't distinguish success from failure. Same pattern
  in logout(), userDetails(), verifyEmail(), and throughout userProfile.ts.

  - DevTools.tsx:55,74,169,193,232,262

  6. usePaymentApplication hits REST endpoints outside wcapi                    
                                                                  
  src/apps/transactions/hooks/usePaymentApplication.ts:159,204,241 — Custom     
  actions (apply_payment, payment_status) bypass wcapi RBAC and audit.
