## Architecture Decisions

| Decision | Why |
|---|---|
| Layer not stack | Layers accumulate, erode, split. Stack implies push/pop. |
| Margin velocity as real fields | Too important for JSON drilling. Must be sortable/filterable. |
| Below-margin alerts never block shipment | Commerce must flow. Flag and ship, review in dashboard. |
| UUID immutable | Product identity across all systems. Changing breaks everything. |
| ida never null | Default to string of id. Every record has a human handle. |
| One UUID per product regardless of vendor | Ingrid resolves identity first, maps vendors second. |
| Price cascade first-match-wins, no stacking | Clear, testable, auditable. |
| refs.links for all relationships | Layer lineage, serial linkage, external IDs — one pattern everywhere. |
| JSON viewer as standalone window | Spawned from DataBrowser, cross-window updates via BroadcastChannel. |
| Commerce Dashboard = one page, four+ tabs | Small businesses need everything in one place. |
| Alice WCHQ coaching = metadata only | Navigation patterns and layouts shared, never business data. |
| Reports in Report model, not hardcoded React | Users customize via pdfme Designer. Alice teaches the process. |
| WC3 produces GL entries, accounting consumes | Never build P&L or Balance Sheet. |
