  Right now nothing prevents uuid from being changed after creation. It should
  be set once and locked. A pre_save check: if self._state.adding is False and
  uuid changed, reject. The uuid IS the product's identity across all systems —
  changing it breaks every external reference.

  2. ida uniqueness scope
  ida is unique within one WC3 instance but two retailers might both use "BB005"
   for different products. When syncing between instances, uuid resolves the
  conflict, but ida collisions need a rule: keep the receiving system's ida?
  Prefix with source? This is a DynamicCatalogs/Ingrid decision — worth
  documenting now.
  
   Bill-comment:  what we did in wc2 was to append the "-" source ida to the itemNum (ida)

  human-readable handle even when nobody assigned one.

  refs.links.external_ids: {
    "amazon_asin": "B00ABC123",
    "upc": "012345678905",

  }

  model can use. Alice can validate UPC check digits, flag duplicate ASINs
  across items.
